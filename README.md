# Отчет о проделанной работе

Это тестовое задание на работу с legacy кодом админки на PHP.

По заданию необходимо провести аудит безопасности системы и исправить все проблемы.

В структуре базы данных есть таблица квартир `NL_PROP_RESALE` и связанная с ней таблица `NL_VIEW` (вид из окна).
Нужно добавить еще две таблицы `NL_HOUSES` (тип дома) и `NL_MATERIAL` (материал дома). 
Связать их с таблицей квартир `NL_PROP_RESALE` и выводить в админку. 
При добавлении квартиры можно выбрать в выпадающем списке тип дома и материал дома.

Также надо добавить лендинг используя шаблонизатор Smarty. В лендинге показать квартиры из базы данных.

Было рекомендовано активно использовать ИИ со своей перепроверкой.

Без сильного рефакторинга: структура файлов, классы и сигнатуры сохранены.

## Аудит безопасности

Сделан с помощью Claude Sonnet 5.5

Рефакторинг разделил на два этапа:

### SQL-инъекции
На первом этапе выполнена защита от SQL-инъекций на mysqli, и исправлены все места, 
где `$_GET` / `$_POST` / `$_REQUEST` / `$_FILES` / `$_SERVER` / `$_SESSION` попадают в SQL 
и в другие места (JS, HTML, пути файлов, include) без проверки;

Подробный отчет по изменениям: [SQL-инъекции](security-audit-1-SQLi.md)

В коде комментарии к правкам из этого пункта отмечены как `[SEC]`

### Защита серверной логики и данных

На втором этапе сделана авторизации в endpoint-ах `admin/php`, функция `AES_ENCRYPT` была заменена хэшированием пароля `password_hash` / `password_verify`,
секреты вынесены из исходного кода в .env, также добавлены CSRF-защита, безопасное управление сессиями и cookie, защита от перебора паролей

На счет `AES_ENCRYPT` сомневался, что может оставить ее. 
Обновления накатывал поэтапно, поэтому в отчете по первому этапу она еще фигурирует в правках. 
Но заменил ее хэшированием на втором этапе, потому что она имеет отношение к безопасности: 
`AES_ENCRYPT` обратим если есть ключ.

```sql
SELECT ID_NL_USER,
      NL_USER_LOGIN,
       CAST(AES_DECRYPT(NL_USER_PASSWORD, 'aes_some_key') AS CHAR) AS PWD_PLAIN
FROM NL_USER
WHERE ID_NL_USER IN (1, 2);
```

Поэтому решил что возможность утечки паролей это повод заменить `AES_ENCRYPT`.

Подробный отчет по изменениям: [Защита серверной логики и данных](security-audit-2-other.md)

В коде комментарии к правкам из этого пункта отмечены как `[SEC-1]... [SEC-7]...` соответсвенно пунктам подробного отчета.
